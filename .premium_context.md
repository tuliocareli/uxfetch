# UX Fetch - Handoff para o Repositório Premium (uxfetch-pro)

Este documento centraliza o contexto técnico do ecossistema do **UX Fetch**. 
Use este arquivo para contextualizar o agente no novo repositório privado (`uxfetch-pro`), garantindo que o agente entenda a infraestrutura existente e como a camada Freemium deve ser acoplada, sem precisar acessar o repositório Open Source.

---

## 1. O Projeto UX Fetch (Visão Geral)
O UX Fetch é uma plataforma gratuita que raspa vagas de Design (UX, UI, Product) e envia um e-mail diário com a curadoria dessas vagas, além de exibir um mural público no site.
- **Domínio Principal:** uxfetch.com.br
- **Motor Principal (Open Source):** Um script em Node.js (Puppeteer) que roda via GitHub Actions diariamente, raspa sites (Gupy, Greenhouse, Solides, Remotar, Trampos), salva no banco de dados e dispara e-mails usando a API do Resend.

## 2. A Camada Premium (uxfetch-pro)
A proposta do repositório Premium é hospedar uma área logada (Kanban Pessoal) cobrada dos candidatos pesados (Heavy Users). Esta camada se conectará **ao mesmo banco de dados** do projeto Open Source, mas rodará em um subdomínio protegido (ex: `app.uxfetch.com.br`).

**Objetivos do Kanban Pessoal:**
- Autenticação via Supabase Auth (Obrigatório focar 100% na integração com o **Google Auth**).
- Uma interface Kanban onde o usuário arrasta as vagas capturadas em colunas (Interesse, CV Enviado, Entrevista, Proposta, Rejeitado).
- *Snapshot de Dados:* Quando um usuário favorita uma vaga do Mural/E-mail, faremos um "deep copy" para a tabela `user_saved_jobs`. Isso garante que a vaga continue no Kanban dele mesmo que o robô apague a vaga pública original após 30 dias.
- Checkout Integrado via Stripe/MercadoPago para flagar o usuário com `is_pro = true`.

## 3. Infraestrutura & Banco de Dados (Supabase)
Toda a infraestrutura de dados já está hospedada em um projeto consolidado no Supabase. O repositório Premium **não** deve criar um novo projeto Supabase, ele deve apontar para o existente usando as credenciais abaixo:

- **Supabase URL:** `https://wxogmhruwhjvhhgmfvrr.supabase.co`
- **Tabelas Existentes (Mural Aberto):**
  - `jobs`: Guarda as vagas do radar (id, title, company, location, url, is_remote, created_at, source, is_international, work_mode).
  - `subscribers`: Guarda a base de leads/assinantes de e-mail (email, city, preferences, last_opened_at, etc).
  - `email_events`: Tabela bruta alimentada por Webhooks do Resend.
  - `platform_stats`: Contadores consolidados.
  - `email_metrics_dashboard`: View SQL das métricas.

## 4. O Que Construir Primeiro no Novo Repositório?
Ao carregar este contexto no novo repositório, os primeiros passos recomendados são:
1. **Configuração Base:** Iniciar um app React/Next.js (ou Vanilla JS) isolado.
2. **Supabase Auth:** Habilitar autenticação (tela de login) para os usuários acessarem o painel privado.
3. **Novas Tabelas (RLS):** Criar no Supabase a tabela `user_saved_jobs` ligada ao `user_id` autenticado. Configurar RLS rigoroso para que um candidato nunca veja o Kanban do outro.
4. **Interface Kanban:** Construir as colunas (UI/UX limpa, darkmode, glassmorphism) e a integração de drag-and-drop.
5. **Endpoint Mágico (Snapshot):** Criar a rota (ex: `/salvar?job_id=XYZ`) que o usuário clicará lá no e-mail dele. Ao clicar, o sistema exige login e, se logado, faz o deep copy da tabela `jobs` para a `user_saved_jobs`.
